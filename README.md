# System Design Learning Journey

A practical, project-based collection of notes for learning system design and becoming a better software engineer.

## Learning goals

- Understand how web applications work end to end.
- Design clean backend APIs and data models.
- Learn scalability, caching, messaging, and distributed systems.
- Build systems, measure their behavior, and explain architectural trade-offs.

## Roadmap

| Weeks | Focus | Practical work |
| --- | --- | --- |
| 1–2 | Web and backend fundamentals | Task Management API |
| 3–4 | Databases and data modeling | Users, projects, tasks, indexing |
| 5–6 | Performance and scaling | Redis cache, rate limiting, load testing |
| 7–8 | Distributed systems | Job queue and notification worker |
| 9–10 | Production readiness | Docker, testing, monitoring |
| 11–12 | Architecture practice | URL shortener and another system design |

## How to study

1. Read the lesson and summarize the concepts in your own words.
2. Run the practical exercises.
3. Draw the architecture without referring to the notes.
4. Answer the review questions and document your findings.

> These notes are learning material. Real production systems may use different transports, caching layers, proxies, and deployment architectures.
